**构建、检索、更新。** `companion.py` 负责服务流程，`memory_support.py` 集中记忆表示、来源与有效性规则。

- `messages` 保留原话及回答。一次问答同时生成解释、可选建议、最多两条个体记录。LLM 判断明确困惑、自己的解释或明确偏好，并提出重复、补充、局部变化或冲突；代码核对原话、归属和字段。来源存在不证明摘要成立，AI 解释过不等于孩子懂了。
- `memoryItems` 增加来源角色、递增版本、范围和关系。家长提醒直接保存，不经模型批准。局部讲法可仅限本会话；新理解保留旧困惑，重复可不新增，不自动覆盖家长意见或恢复撤回项。
- `begin_chat → prepare_context` 从当前档案有效记录和过去会话构建临时目录，上限 80 项/28000 字节，超限明确降级。它不是旧关键词前十二条。一次同模型语义选取最多四条个体记录；回顾或核对原话时可选最多两个会话。取回 ID 后重新核对内容、版本、状态。无关问题允许空结果。
- 本次对话取最近 14 条；回顾优先取有效小结，核对原话或小结不可用时取对应会话最近 10 条有效原文。小结保存在 `conversations.exploration`，含主题、困难、尝试、未解决问题、来源 ID 和记录版本。结束会话或手动整理时异步生成，最多两个本地任务；取最近 30 条、每条最多 1000 字，超出时标为部分整理。同一来源指纹直接复用。
- `update_memory / invalidate_pending / blocked_messages` 使依赖旧版本的上下文、小结、建议失效。历史原话仍可回看，旧判断退出后续生成资料；最新建议失效后不回退展示更早活动。在途回答取消，整理提交前复核来源和家长修订，重启不续写旧任务。服务端保存实际提供的 `providedMemoryVersions / providedExplorationVersions`，`usedMemoryIds` 仅是模型自报。

检索失败时页面说明未能核对历史，普通问答可继续，不能声称采用未读到的提醒。密钥、权限、预算错误直接停止，没有自动重试或审核模型。旧版回答只有部分自报依据，无法事后补齐全部输入依赖，这是迁移边界。
