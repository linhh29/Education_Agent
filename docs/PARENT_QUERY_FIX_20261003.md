## 根因与首次复现

已阅读 `MANUAL_ACCEPTANCE_20261003.md` 的完整请求顺序、原文、页面状态和对应合成记录。原报告保持不变。

家长请求的 `begin` 只保存孩子、文字、目标记录、状态和时间，没有保存整个档案的版本或全库 fingerprint。`context` 先读取独立快照，调用 `parent_select`，随后为选中资料建立 `memoryVersions`（ID+version）与 `sourceMessageIds`。`work` 在选择后、回答落库前分别检查归属、删除/撤回、版本、依赖有效性和偏好替代状态；并没有因为全库排序或任意资料更新而一律拒绝。

实际故障来自两处契约不一致：

1. 选择目录已经排除了被纠正的旧偏好 `mem_f37b39b4061a43de`，当前偏好为 `mem_1d5e7cbcaba34204`。
2. 选中已结束会话 `conv_c040fe52462946d5` 后，其 exploration 的历史 `memoryVersions` 又调用 `add_record`，把旧偏好加入当前回答依据。
3. `valid_result` 正确识别该偏好已被替代，因而在调用 `parent_answer` 之前返回“依据刚有更新”。即使没有任何并发修改，重试仍可失败。

首次复现使用报告的真实合成资料副本、真实 ParentService 和受控选择器；原调用未保存选择器原始输出，因此没有声称逐字重放原模型选择结果。选择目录中的原会话就能复现：旧偏好重新出现于依赖中，请求 failed，孩子四张业务表前后完全一致。没有真实API调用。

首次证据：`/private/var/folders/lc/432p1rq17gl0fl1qvf8df_3c0000gn/T/parent-query-fix-1u42ag5h/first-reproduction.json`。修复后相同输入、相同受控选择转为 completed；`retiredInEvidence=[]`，旧原话仍可引用，孩子资料仍未改变；对应 `reproduction-fixed.json`。

内部字段故障来自 `parent_ad03ccb18c744672.text` 本身含有 `action: add`、`memoryId: 空`、`summary:`、`topic:`、`scope:`。前端只是渲染正文，并不是把 draft 对象错误遍历出来。原有 `clean_advice` 仅清理 advice，正文和旧AI历史没有经过相同结构投影。

## 修改范围

仅修改 `parent_support.py`、补充 `tests/test_parent.py`，以及本说明。

- 在 `add_record` 这一共用入口执行当前有效记录过滤，防止小结或继承入口绕过选择目录。原话继续作为历史依据，旧偏好不再充当当前偏好。没有修改全局 memory validity、scope、提取或检索算法。
- 复用现有清理机制为 `clean_parent_prose`，依据父端 JSON schema 的字段集合处理序列化对象、字段行、代码围栏和多行结构。分别投影 answer/advice，草稿、活动与来源保留在各自结构字段中，不针对海豚、恐龙或某段回答写特殊规则。
- 新正文落库前清理；历史AI正文在读取和提供给家长模型历史时清理，旧磁盘记录不改写；家长自己的原话不清理或替换。
- 两处 staleness 检查、真实版本/归属保护、幂等机制均保留，没有添加模型调用、审核链或自动重试。

孩子回答prompt、模型配置、memory scope、活动逻辑、语音、前端文件均无改动。原报告的其他问题保留，本轮不修。
